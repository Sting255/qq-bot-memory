# Cortico 思路接入方案：三件套

> 来源：Pal-AI-Lab/Cortico（AGPL-3.0，只借鉴思想，不搬代码，与 AstrBot 同样处理）。
> 三件事互相独立，可分别实施；都跑在你现有架构上，不动 pipeline。

## 一、交接笔记：中期记忆的「始终在场版」

### Cortico 的做法（handoffNote.ts）
上下文交接时生成一份"最近发生了什么"的笔记注入新上下文，关键是**分层折叠预算**：
- 最近 1/4 的条目给满预算（每条最多 1024 token）
- 再往前 1/4 给 1/4 预算
- 更早的条目只留开头
- 按 token 预算由近到远装满为止，装不下的早期条目只记录数量

### 你的现状与差距
`mid-term.js` 已有摘要+召回线索，但它是**按需召回**的：当前对话要"命中线索"才出现。
这有个盲区：**刚被裁出上下文的那段对话，如果当前消息和它的线索不相似，就完全消失**——
而它明明是"刚刚还在聊的事"，本该无条件在场。

### 接入方案
新增「recent-notes 块」，与召回的 mid-term 并行注入：

1. `recallRecentNotes(conversationId)`：取最近一条 mid-term 记忆（按 sourceRawEndId
   最大的那条），**不做相似度匹配**，只要它的时间在 N 小时内（默认 6h，config 可调）
2. `formatMidTermBlock` 渲染时，区分两种来源：
   - 命中召回的 → 现有格式
   - recent-notes → 加时间标注："（这是 {time_range} 的对话脉络，一直供你参考）"
3. 防重复：同一条记忆既被召回又被 recent 命中时，只渲染一次，标注合并
4. 超过 N 小时后 recent 块自动退场，只剩正常召回路径

### 折叠策略（Cortico 的年龄衰减，简化版）
不动 mid-term 生成本身（那是 LLM 压缩，已经稳定），只加在**渲染层**：
- recent-note 的 summary 超过 500 字时，保留前 200 字 + "…"（老的记忆本来就该粗）
- 一条完整 summary 说明它刚生成，给全额；这比 token 级折叠简单，效果够用

### 优点
- 补上"刚裁出上下文的对话无条件在场"这个盲区，成本几乎为零（复用现有表和生成流程）
- 群里换话题又换回来时（30 分钟前聊的事），不再依赖线索命中的运气
- 不改 prompt 主结构，只在 formatMidTermBlock 加一个来源

### 工作量
store.js 加一个查询（~15 行）+ mid-term.js 加 ~30 行 + 单测。半小时级。

## 二、心跳主动性：trigger/ 的「有机会说话」层

### Cortico 的做法（heartbeat.ts）
- 基线间隔 baseline(now) 返回此刻该不该心跳（可热更新，30 分钟复查一次策略）
- 连续空拍时间隔逐次翻倍，上限 8 倍；**任何外部事件到达立即复位**到基线
- 心跳 tick 只是"给 Bot 一个开口的机会"，说不说仍由模型/策略决定

### 你的现状与差距
`trigger/scheduler.js` 是纯被动概率门控（消息驱动），`idle-backoff.js` 有退避但
服务于判定而非主动性。你的机器人**永远不会在没人说话时开口**——而"冷场时偶尔
冒一句"正是拟人化的高光时刻，且你的记忆库里全是素材（curate 出的判断句）。

### 接入方案
新增 `trigger/heartbeat.js`：

1. 基线间隔：`heartbeat.baselineSec`（默认 1800s，config 可调）
2. 空拍退避：连续无事件的 tick 间隔 ×2、×4、×8 封顶；任何消息到达 `noteActivity()` 复位
3. tick 触发时**不直接回复**，走一条专用低频路径：
   - 检查冷却（同会话 1 小时内没主动开过口）
   - 从最近记忆里挑一条（memory_fragments 表按时间取近的 5 条）
   - 调一次 LLM 判定"此刻值不值得说话"（类似 judgeImageIntent 的单次判定），
     prompt 给它当前群静默时长 + 近期记忆 + 人设，输出要发的话或空
   - 值得说 → 走正常 persona 分段发送；不值得 → 静默
4. 上限保护：每天每会话最多 N 次主动发言（默认 3），存 conversation_state

### 优点
- 补齐"主动性"这块人格 Bot 的核心体验，且默认参数极保守（30 分钟基线 + 日限 3 次），
  不会变成刷屏机器人
- 事件复位机制天然适配群聊：群里越热闹越不需要它开口，冷场越久越可能冒一句
- 判定权交给 LLM + 你的记忆库，不是机械模板——正符合 Cortico「最小先验干预」

### 风险与对策
- 主动说蠢话的风险 → 判定 prompt 要求输出空串则放弃；上线前先在测试群观察
- 与概率门控打架 → heartbeat 完全独立于 scheduler，走 _sendPlain 类轻量路径，
  不占用 recordReply 的闭环统计（不污染概率模型）

### 工作量
~150 行 + config 段 + 单测。一小时级。

## 三、宪法/经历分离：prompt.md 定位明确化

### Cortico 的做法
CONSTITUTION.seed.md：人格核心 = 一份普通文件，每次 session 进 system prefix，
Bot 自己可改写。"Memory 即人格：换模型、交接、重启不改变个体身份"。

### 你的现状与差距
人格散在三处：`src/chat/prompt.md`（静态）、`bot_persona` 表（面板可编辑）、
memory（经历）。边界没明确——prompt.md 里可能混进易变内容（比如临时状态），
而 bot_persona 表又可能被塞进本该稳定的特质。

### 接入方案（最轻，纯纪律 + 小改）
1. `prompt.md` 头部加注释定位：**宪法区——只放稳定特质（身份、说话风格、价值观、
   硬边界），任何易变内容（近况、临时设定、正在做的事）禁止写在这里，走记忆系统**
2. `renderSystemPrompt` 渲染时把宪法和 bot_persona 表的内容用明确的分隔注释拼装：
   `/* 人格宪法（稳定）*/` + `/* 动态设定（面板可改）*/`
3. 不引入"Bot 自改写宪法"——风险大于收益，你的面板编辑已够用

### 优点
- 零运行时成本，纯结构纪律
- 以后人格漂移、debug"它为什么这么说话"时，一眼能分清是宪法问题还是记忆问题
- 与你"规则越少效果越好"的实测结论同源：宪法短而稳，易变的交给记忆

### 工作量
prompt.md 加注释 + persona.js 拼装处 ~10 行。十分钟级。

## 实施顺序与验收

| 顺序 | 项 | 工作量 | 验收 |
|---|---|---|---|
| 1 | 宪法定位 | 10 分钟 | prompt 结构注释清晰，测试全绿 |
| 2 | recent-notes | 半小时 | 手测：聊一段→等裁出→换无关话题→脉络仍在上下文 |
| 3 | 心跳主动性 | 1 小时 | 测试群观察 3 天：主动发言 ≤3 次/天且内容合理 |

三项都不动 pipeline、不改 LLM 调用主链路，随时可单独回滚。
